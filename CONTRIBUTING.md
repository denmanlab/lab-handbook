# Contributing to the lab handbook

## How to change a page

1. Open a pull request. Don't commit to `main` directly.
2. Describe *why* in the PR body — the diff shows what changed, not the reason.
3. Policy pages (`policy/`) need Dan's review before merging.
4. Computing pages (`computing/`) can be merged by any lab member after one review.

## What belongs here

Policy, expectations, onboarding, and computing conventions — documents that apply to
the lab as a whole and benefit from reviewed, versioned history.

## What does not belong here

| Instead of here… | Put it in… |
|---|---|
| A protocol or SOP | eLabFTW |
| An experiment record | eLabFTW |
| This week's task list | Slack |
| Analysis code | its own repository |
| Anything about a specific person | not on a shared platform |

## Public repository

This repository is public. Before committing, check for: internal IP addresses or
hostnames, URLs to private documents, personal contact details, and unpublished data.
Use the lab's public hostnames rather than internal addresses, and link to access-
controlled resources by name rather than URL.
